## Что это и зачем

Это **рабочая база знаний по продукту AI-Маркетолог** — образовательной программе Влада Яско на тему AI-инструментов для маркетинга, продаж и контента. «Один человек заменяет отдел из 12. Завод в кармане».

База устроена **в двух слоях**:

1. **Seed-документы** (папки `product/`, `content/`, `landing/`, `research/`, `team/`, `resources/`) — операционные документы продукта: оффер, программа, воронка, ToV, кейсы. Это то, с чем работаешь каждый день.

2. **`university/`** — Zettelkasten-база знаний по методологии [kkarpushin/university-template](https://github.com/kkarpushin/university-template): атомарные заметки, проверяемые claims с implications для проекта, и сводные syntheses. Это то, к чему обращаешься, когда нужно **обосновать решение или сверить курс с фактами**.

## 🛠 Как работать с базой

### Сценарий 1: «Мне нужно написать пост / рилс / лендинг»

1. Открой соответствующий synthesis (syn-offer / syn-funnel / syn-methodology)
2. Найди claims с implications — там готовый product behavior
3. Sneji [`content/02_tone_of_voice.md`](content/02_tone_of_voice.md) — ToV Влада
4. Если упомянутый факт нужно проверить — открой связанный note или seed-документ

### Сценарий 2: «Появился новый источник (статья / видео / кастдев)»

1. Прочитай [`university/METHODOLOGY.md`](university/METHODOLOGY.md) §4 — 10-шаговый пайплайн обработки
2. Если URL — положи в `university/queue/inbox.md`
3. Обрабатывай по пайплайну: source → notes → claims → synthesis → graph → INDEX
4. **Когда работаешь через Claude Code из этой папки** — обработка URL идёт автоматически (см. memory ниже)

### Сценарий 3: «Хочу проверить, не противоречит ли наше новое решение тому, что мы уже знаем»

1. Открой `university/syntheses/` — релевантный по теме
2. Раздел Strategy implications — там декларированные правила
3. Если новое решение противоречит — зафиксируй как `university/contradictions/contr-NNN.md` (см. METHODOLOGY §10)
4. Разрешение конфликта = новый claim или обновлённый старый

### Сценарий 4: «Хочу подключить Claude Code к этой базе»

Если ты работаешь через Claude Code и запускаешь его из папки `ai-marketolog/`:

- Memory автоматически активирует правило: **любой URL → через university pipeline**
- Файл правила: `~/.claude/projects/<slug>/memory/reference_url_summary_workflow.md` (если у тебя нет — скопируй из примера в `memory-template/` университетского репо)
- Это значит: кидаешь Claude URL в чат — он сам обрабатывает по 10-шаговому пайплайну, добавляет в notes/claims/INDEX

## 📜 Откуда эта структура

База использует методологию **Zettelkasten-фреймворка** [kkarpushin/university-template](https://github.com/kkarpushin/university-template) (Константин Карпушин). Принципы:

- **Одна идея = один файл** (atomic notes)
- **Проверяемые утверждения** с evidence (claims) и implications для проекта
- **Перекрёстные ссылки + граф** между всеми артефактами
- **Sources** — первоисточники неизменяемы; интерпретации в conspect/notes/claims
- **Никаких автоправок продукта** — изменения в реальной программе/лендинге/коде только после явного решения

Это **переносимый и расширяемый формат** — любой коллега-маркетолог может открыть, понять структуру и развивать дальше.

## ⚠️ Что НЕ нужно делать

- ❌ Не редактировать seed-документы «по живому» без фиксации в contradictions. Если seed устарел — пометить и обновить через claim.
- ❌ Не сливать notes в один длинный документ. Одна заметка = одна идея. Если в заметке две идеи — разделить.
- ❌ Не писать claims без evidence (без ссылок на notes/sources). Нет доказательной базы → нет claim.
- ❌ Не использовать ToV Влада дословно для других проектов (см. c-0004).
- ❌ Не размывать стек Claude Code добавлением «давайте ещё Cursor». Это часть отстройки (см. c-0006).
- ❌ Не монетизировать веб (см. c-0007).

## 📍 Дальнейшие шаги

После прочтения этой базы коллега-маркетолог может:

1. **Продолжать развивать syntheses** — добавлять новые claims, обновлять confidence по мере новых данных
2. **Атомизировать дополнительные seed-документы** (Q&A Потока 1, кейсы стратсессий — ещё много непереваренного)
3. **Обрабатывать внешние URL** через `queue/inbox.md`
4. **Создавать contradictions** при конфликте новых данных с старыми claims
5. **Открывать `verdicts/`** для финальных стратегических решений
